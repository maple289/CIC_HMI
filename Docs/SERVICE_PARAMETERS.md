# Service parameter adjustment support — 2026-11-05

The existing per-card three-dot menus and one-parameter editor are reused. No Service-page redesign or operating-command changes. All named setting writes now require Administrator, explicit confirmation, fresh matching identity/value/status/lock checks, single transmission, readback and audit. Other roles may view and refresh. Physical writes remain limited to the previously authorized 670 capability; documentary access is not hardware validation or a generic write grant.

The 700 overview/calibration guidance on p73 additionally requires a standard-type span target at least 100 °C and dilution-type target at most 70 °C for a valid calibration; the register table itself permits 50–150 °C. Operators must choose an appropriate target for their model before calibration. Firmware-specific deviations beyond the supplied manuals are unverified.

LATCHES exposes only the four documented alarm relay bits on legacy families; valve/ignition/heater and reserved bits are preserved. 700 latch controls are separate 0/1 registers, and unexpected upper bits block writing. Register 18 is rejected by the common encoder/validator, worker service and physical transport, including forged requests. Refresh requests use FC03 on the existing serialized worker/bus and report communication errors separately from unsupported settings. No parallel polling engine, automatic persistence command, retries after uncertain writes or prohibited writes were added.

Outstanding verification: BTU/FID numeric bounds; FID FAILSAFE remote-write behavior/safe mask; firmware-specific physical compatibility, actual lock semantics, relay effects, readback and persistence for all newly supported physical profiles. Simulator tests do not release those gates. Any future physical capability requires a separate verified procedure and firmware scope.
